# Code Review — Ревью кода

Источник: [anthropics/claude-code/plugins/code-review](https://github.com/anthropics/claude-code/tree/main/plugins/code-review) (Anthropic)

Автоматизированный code review для pull request-ов с использованием нескольких специализированных перспектив и confidence-based scoring для фильтрации ложных срабатываний.

---

## Методология

Ревью проводится по нескольким независимым направлениям параллельно:

### Направление 1: Соответствие стандартам проекта
- Проверь файлы конфигурации проекта (CLAUDE.md, AGENTS.md, .eslintrc, etc.)
- Аудит изменений на соответствие зафиксированным правилам
- Цитируй конкретное правило при нарушении

### Направление 2: Поиск багов (только в diff)
- Сканируй только diff, без дополнительного контекста
- Отмечай только **значимые** баги
- Игнорируй nitpicks и вероятные false positives
- Не отмечай issues, которые невозможно валидировать без контекста вне diff

### Направление 3: Проблемы в новом коде
- Ищи security issues, некорректную логику
- Только в пределах изменённого кода

### Направление 4: История и контекст (git blame)
- Анализ git blame/history для context-based issues
- Понимание как изменения влияют на существующий код

---

## Фильтрация: Только HIGH SIGNAL issues

**Отмечай issues где:**
- Код не скомпилируется или не парсится (синтаксические ошибки, ошибки типов, отсутствующие импорты)
- Код **точно** даст неверный результат при любых входных данных (явные логические ошибки)
- Чёткие, однозначные нарушения стандартов проекта (цитируй конкретное правило)

**НЕ отмечай:**
- Стиль кода или quality concerns
- Потенциальные issues, зависящие от конкретных inputs или state
- Субъективные предложения или улучшения

**Если не уверен — не отмечай.** False positives разрушают доверие и тратят время ревьюера.

---

## Процесс ревью

1. **Предпроверка** — PR закрыт? Драфт? Тривиальное изменение? → пропусти
2. **Собери стандарты** — прочитай конфигурационные файлы проекта
3. **Суммируй изменения** — пойми что и зачем менялось
4. **Проведи 4 параллельных ревью** — каждое направление независимо
5. **Валидация** — для каждого найденного issue проверь его обоснованность
6. **Фильтрация** — оставь только валидированные issues с высокой уверенностью
7. **Отчёт** — суммируй результаты

---

## Формат отчёта

Для каждого issue укажи:
- **Файл и строка**
- **Описание проблемы**
- **Причина** (баг, нарушение стандартов, security)
- **Уверенность** (только 80%+ попадает в отчёт)

Если issues не найдены:
> "Issues не найдены. Проверено на баги и соответствие стандартам проекта."
