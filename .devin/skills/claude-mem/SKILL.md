# Claude-Mem — Persistent Memory

Источник: [nicholasgasior/claude-mem](https://github.com/nicholasgasior/claude-mem) (MIT)

Система persistent memory для сохранения контекста между сессиями разработки. Автоматически захватывает наблюдения, генерирует семантические сводки и делает их доступными в будущих сессиях.

---

## Концепция

Проблема: каждая новая сессия начинается с нуля — теряется контекст о проекте, решениях, паттернах, подводных камнях.

Решение: автоматическая фиксация важных наблюдений → сжатие → инъекция в будущие сессии.

---

## Что фиксировать

### Архитектурные решения
- Почему выбран конкретный подход
- Какие альтернативы рассмотрены и отклонены
- Ключевые архитектурные паттерны проекта

### Технические наблюдения
- Особенности настройки окружения
- Зависимости и их версии
- Нетривиальные конфигурации
- Известные баги и обходные пути

### Контекст проекта
- Структура кодовой базы и ключевые файлы
- Паттерны именования и стиля
- Workflow разработки (ветвление, CI/CD, деплой)
- Тестовые аккаунты и окружения

### Решённые проблемы
- Баги, которые были сложными в отладке
- Их корневые причины и исправления
- Подводные камни, которые стоит помнить

---

## Формат записей

Каждая запись должна быть:
- **Краткой** — 1-3 предложения, без воды
- **Конкретной** — точные файлы, команды, версии
- **Актуальной** — полезна для будущих сессий, а не только для текущей
- **Контекстной** — достаточно информации, чтобы понять без дополнительного контекста

### Пример

```markdown
## Настройка БД
- PostgreSQL 15 на порту 5432, пароль в .env.local
- Миграции: `npm run db:migrate`, сидинг: `npm run db:seed`
- При ошибке "relation does not exist" — пересоздать БД: `npm run db:reset`

## Архитектура API
- REST API на Express, маршруты в src/routes/
- Auth через JWT, middleware в src/middleware/auth.ts
- Rate limiting: 100 req/min per IP на /api/*
```

---

## Практика сохранения контекста

1. **В начале сессии** — прочитай сохранённый контекст, обнови если устарел
2. **При решении проблемы** — запиши корневую причину и решение
3. **При обнаружении паттерна** — запиши паттерн и где он применяется
4. **При настройке окружения** — запиши точные шаги
5. **В конце сессии** — сохрани ключевые наблюдения

---

## Интеграция с Devin

В Devin используй:
- **Knowledge Notes** — для записи наблюдений через `suggest_knowledge`
- **SKILL.md файлы** — для фиксации процедурных знаний через `suggest_skill_pr`
- **Blueprint** — для фиксации настроек окружения через `devin_env`

Цель: каждая следующая сессия начинается с полного контекста предыдущих.
